# 空间清理

空间清理使用独立导航，与体检评分分开。进入页面不会扫描或选择文件；点击「开始扫描」后，默认检查当前用户的常用位置。也可以只检查 Xcode、下载文件夹，或明确选择其他目录。

## 扫描与分类

- 默认位置包括已知浏览器与依赖缓存、其他用户缓存、诊断记录、Xcode DerivedData 与 Archives、开发构建、下载内容，以及 Application Support 下的发布档案。发布档案发现只读取相应位置，不把 Application Support 整体视为缓存。
- 系统目录、其他用户、外接卷和未下载的云端占位内容不自动纳入。权限不足、缺失目录、符号链接、重复身份以及扫描数量与深度限制分别记录，不能据此声称覆盖了整块磁盘。
- 「可重建内容」使用明确路径和内容规则；DerivedData 单独识别构建与索引位置。近期诊断、锁文件、数据库和运行中的关联应用内容保留。其他文件进入人工复核，不根据体积或修改时间自动推荐。
- 默认三组均不勾选。「选择建议项」是用户主动动作。取消或失败的扫描仅供查看；达到数量或深度边界时明确展示覆盖不足，只有已完整核验的项目可以继续复核。
- 容量条显示系统报告的磁盘占用；候选大小是扫描到的逻辑大小，不等于实际可释放空间。稀疏文件、克隆、快照、硬链接和废纸篓会影响实际占用。

## 测试包与发布材料

发布档案、已识别的 Organizer 分发归档、关联符号和更新材料可查看但受保护。已安装和正在运行的 App 不通过此功能卸载。签名、公证、名称、大小或年代本身均不能证明一个 App 是测试副本。

未知 App 与归档默认保留；用户逐项确认仅用于测试后，使用绑定当前文件身份及目录内容的声明重新扫描，之后仍需手动选择。声明不会覆盖发布材料、运行状态、包内部边界等保护规则；文件变化后旧声明失效。普通测试 App 中的安全内部相对链接按完整包处理，不拆开清理。

## 处理与恢复

默认移到废纸篓，也可选择永久删除并保存处理方式偏好。永久删除每次都必须重新勾选确认；保存偏好不跳过确认。

每个项目在执行前重新核对根目录、祖先目录、对象身份、内容及保护规则。处理使用同卷私有隔离目录和无覆盖移动，意图与结果逐项写入本机历史。取消只停止后续操作，当前项目完成必要的安全收尾；退出 App 等待该屏障。

移到废纸篓不记为已经释放空间。历史可按批次或按项恢复；遇到原位置同名文件时，选择保留两份或跳过，不覆盖现有文件。「永久删除剩余项目」仅处理指定批次中身份与内容仍然匹配的项目，不清空系统废纸篓。永久删除不可恢复。恢复及处理后，原扫描选择失效，需要重新扫描。

历史损坏或无法可靠保存时，保留原记录并暂停文件处理。重启只核验未完成意图和可恢复位置，不重放删除操作。无法确认位置的项目保留人工核对说明。早期清理记录仍通过原服务访问。

## 实现与验证

`SpaceCleaningCore` 负责只读扫描、识别和政策核验；`SpaceCleaningTransaction` 负责内容证据、持久历史、隔离、恢复及永久删除。原生模型连接系统废纸篓、文件选择器、快速预览、运行应用与磁盘读数，视图复用工作台材质、导航、滚动与弹窗。

核心测试以及 `--space-cleaning-check` 使用隔离测试目录和注入的废纸篓实现。专项检查同时验证真实模型流程与普通、窄、大窗口中的生产 SwiftUI 界面。常规 `--self-check` 包含这些检查；系统权限与真实用户目录的覆盖情况仍以运行时结果为准。
