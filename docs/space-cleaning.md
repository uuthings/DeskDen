# 空间清理

空间清理使用独立导航，与体检评分分开。进入页面不会扫描或选择文件；选择全部范围并点击「开始扫描」后，一次检查当前用户的已知缓存、开发、下载和个人文件位置。自定义范围可组合下载、文稿、桌面、图片与影音、应用缓存、开发与归档六类位置，也可通过系统选择器添加其他文件夹。

首页以左侧磁盘概览和右侧扫描配置组成双栏。细容量柱从下到上分别为已用、系统按需回收估算、立即空闲，各段按真实容量比例绘制；百分比独立显示，右侧三行统一对齐名称、数值和单位。可用空间包含按需回收估算，下方构成条按可用空间归一，不能与回收估算再次相加。缺失读数显示不可用，真实零保留为零，系统未提供估算时明确说明。百分比向下取整，颜色按原始比例判断，达到 90% 显示红色。

扫描配置突出清理／大文件两张模式卡。六类范围采用轻量选项，足够宽时三列两行，较窄时两列三行；范围说明直接融入表面，减少嵌套边框。大窗口的范围选项增加对应路径预览。点击范围卡查看具体路径、检查内容与处理提示；自选时通过独立勾选控制是否纳入扫描，查看说明不会改变范围。目录选择、大小上下限及安全书签继续保留。旧自选配置没有范围分组时不自动增加扫描位置。取消草稿保留原范围和结果，保存范围不自动扫描；空自选范围不能开始扫描。默认窗口完整展示两栏正文、容量说明与扫描操作。容量柱保持细长比例，紧凑布局按余高调整，大窗口将容量读数与可用构成连续排布；分区间距设上限，保留全部信息和正文可读性。只有进一步缩短窗口、展开长范围说明或添加较多自选目录而确实超出时，正文才独立滚动，底部扫描操作保持可见。已有结果时，下方单独显示上次扫描摘要，入口回到现有结果。

扫描过程使用完整可用高度：左侧显示发现、核验和整理阶段，右侧显示实际检查数量、候选数量、候选逻辑大小、当前路径和最近检查的路径。发现阶段总量未知时保持不定进度，不伪造百分比；最近路径只是采样展示，不等于清理建议。完成后进入结果。窄窗口允许卡片重排及内部滚动，不压扁顶部说明和操作区。卡片正文与辅助信息使用共享的 12／11 点字号，常规操作高 32 点、紧凑操作高 28 点。

## 扫描与分类

- 首页可选择「空间清理」或「大文件扫描」，两种模式复用全局／自定义范围。大文件默认下限 100 MB，可选 500 MB、1 GB 或自定义 MB／GB，下限必填、上限可选，单位按十进制计算。阈值针对普通文件的逻辑大小；目录与 App、文稿包不拆开当作普通大文件。权限与保护边界同样适用。
- 大文件模式从文件元数据尽早筛选，默认按文件大小降序，所有结果均不预选，即使文件恰好属于已知缓存。大小只是查看依据，不证明可以删除。显示逻辑大小和磁盘占用，汇总与已选占用按已分配大小计算；稀疏文件不能把逻辑长度计成可释放空间，APFS 克隆和快照也可能使实际回收量不同。
- `node_modules`、`.git`、`.venv`、`venv`、`bower_components`、`__pypackages__` 以及具有普通 `pyvenv.cfg` 标记的环境保持保护。名称只是保守保留依据，不证明内容可重建；默认不会深入统计内部容量或逐个提供删除。展开详情后可主动选择「仅统计占用」，只读普通文件元数据、不跟随链接、不跨卷，并限制条目与深度；支持取消，完整、部分和未知容量分别展示，统计不会解除保护。直接选择内部目录、通过链接选择目录、旧扫描结果及历史永久删除也不能绕过保护；已有废纸篓记录仍可恢复。npm 等下载缓存与安装后的项目依赖分开识别。
- 默认位置包括已知浏览器与依赖缓存、其他应用缓存、诊断记录、Xcode DerivedData 与 Archives、开发构建、下载内容，桌面、文稿、影片、图片、音乐、公共、开发和用户应用目录，以及 Application Support 下的发布档案。发布档案发现只读取相应位置，不把 Application Support 整体视为缓存。
- `~/Library/Caches` 下的每个子目录按单个应用的缓存目录处理：名称形如 `cn.example.app`、`org.swift.swiftpm` 也不视为 App 或文稿包，不提供测试用途确认；它们进入人工复核，内含数据库、锁文件或链接时整体保留。已知缓存位置（如 SwiftPM 缓存）因此按各自规则扫描，不会被当作包跳过。`Google`、`Firefox` 目录下除已知浏览器缓存以外的子目录（如 `Chrome-headless`）同样各作为一个缓存目录复核，不逐个文件展开。
- 系统目录、其他用户、外接卷和未下载的云端占位内容不自动纳入。权限不足、缺失目录、符号链接、重复身份以及扫描数量与深度限制分别记录，不能据此声称覆盖了整块磁盘。发现阶段某个目录超过深度上限时只跳过该目录，同级目录和后续范围继续扫描，并标注覆盖不足。
- 「可重建内容」使用明确路径和内容规则；DerivedData 单独识别构建与索引位置：顶层及各项目目录、自定义 `-derivedDataPath` 根目录下的 `ModuleCache.noindex`、`SDKStatCaches.noindex`、`CompilationCache.noindex`、`SymbolCache.noindex`、`SDKExplicitPrecompiledModules`、`Index.noindex`，以及 `Build` 下的 `Intermediates.noindex` 与 `Products`。其余项目子目录（如 `Logs`、`SourcePackages`、`TextIndex`）各作为一项人工复核，不逐个文件展开；含 Git 资料的 `SourcePackages` 整体保护。DerivedData 中的调试符号和校验文件按构建产物处理，发布目录与 Organizer 分发记录仍受保护。近期诊断、锁文件、数据库和运行中的关联应用内容保留。其他文件进入人工复核，不根据体积或修改时间自动推荐。
- 关联应用按 Bundle ID 与应用名称共同判断，Safari、Chrome、Firefox 和 Xcode 改名后仍能识别；Xcode 构建服务同时识别 XCBBuildService 与 SWBBuildService。npm、Homebrew、pip 由解释器启动，只有 node、bash／ruby、Python 进程实际运行这些工具的脚本时才算正在使用，无关的 Node、Ruby、Shell 或 Python 进程不影响判断。读不到进程列表时按所有工具都在运行处理；其他用户的 Node 进程无法核对脚本时，按 npm 正在使用处理。扫描、默认勾选和执行前复核使用同一套判断。
- 建议列表与默认勾选使用两层规则：列表包含值得整理的候选；默认勾选只包含明确识别、内容核验完整且当前未命中使用或保护规则的浏览器缓存、依赖缓存和 DerivedData 可重建内容。可重建缓存规则之外的安装介质，以及诊断日志、个人文件、测试包与未知内容不自动勾选；默认勾选不执行任何文件操作。
- 结果默认显示「建议清理」，与「其他文件」「已保护」分开。没有符合规则的推荐项时明确说明原因。列表展示名称、父目录、类型、修改日期和大小，支持加宽搜索、查看全部已选以及当前可见项全选；名称、所在目录、类型、修改日期、大小均可点击表头排序，再次点击反转方向。相同值按路径稳定排列，排序和筛选不改变勾选身份；表头和每行使用相同的选择控件。建议清理中不会默认勾选的项目（安装介质、旧诊断记录）在名称旁显示 11 点「需手选」轻标签，标签不截断、不改变行高；旧诊断记录属于人工复核，详情按「处理前请复核」说明，不按可重建缓存展示。符号链接（任何模式）以及大文件模式下低于下限的云端占位、开发标记和特殊文件不会被处理，也不逐行列出，而是按目录汇总在范围说明中；「已保护」底栏显示「另有 N 项已汇总」并可打开说明，保护规则不因此改变。选择文件后在右侧详情卡查看和预览，或在 Finder 中定位；只有缓存、保护及用途确认等具体规则展示处理说明，不重复普通文件的通用提醒。结果摘要、横向分类与底部操作区独立固定，列表内部滚动。详情默认收起，点击项目打开，再次点击同一项目保持展开；勾选不打开详情。详情标题和底部操作固定，正文滚动条贴卡片右缘；右上角使用紧凑的侧栏折叠图标。
- 扫描先发现项目，再逐项核验。发现阶段总量未知，不显示估算百分比；核验阶段用已完成项目数与已发现总数计算进度。发现与核验分别使用有界预算，避免大型个人目录挤掉已发现缓存的核验机会。核验阶段每个目录候选单独受条目与深度上限约束（默认 10 万项），超出时只保留该项并说明「超过单项核验上限」，不影响其他候选；全部候选另有总量上限（默认为单项上限的 5 倍），达到后其余项目保留并标注覆盖不足。因此一个大型缓存不会让其他缓存失去核验机会，关闭浏览器等关联应用也不会挤掉其余缓存的推荐。核验时优先处理已识别且未受保护的可重建候选，开发环境目录只识别边界，容量需主动选择「仅统计占用」；其他保护目录沿用有界容量统计，并保留具体保护原因。取消或失败结果仅供查看；达到数量或深度边界时显示覆盖不足，未完成核验的项目不会选中。
- 扫描位置采用独立草稿。取消或保存未变范围保留现有结果与勾选；范围改变后清空旧结果、回首页，等待用户开始扫描。重叠目录合并，保存安全作用域书签供下次使用。
- 容量柱显示系统报告的磁盘占用；列表区分文件大小与磁盘占用，受保护且未统计的目录显示未知，不以零表示其大小。汇总并不承诺实际释放量，稀疏文件、克隆、快照、硬链接和废纸篓会影响实际占用。

## 整理建议与默认选择

规则先判断保护、使用状态、文件身份及核验是否完整，再判断是否值得整理，最后决定是否默认勾选。允许手动处理不等于自动推荐，出现在建议列表也不等于已经选中。

| 内容 | 识别依据 | 结果分类 | 默认勾选 |
| --- | --- | --- | --- |
| 浏览器、依赖及 Xcode 可重建缓存 | 已知位置、明确内容规则、完整核验且关联应用或工具未运行 | 建议清理 | 是 |
| 文件式 PKG 安装包 | 已扫描位置中未命中可重建缓存规则的普通 `.pkg` 文件，且不在开发项目、构建产物或依赖中；优先排除保护规则 | 建议清理，标注手动选择 | 否 |
| 下载、桌面中的 DMG | 当前用户 Downloads/Desktop 下、不在开发项目、构建产物或依赖中的普通磁盘映像文件 | 建议清理，标注手动选择 | 否 |
| 旧诊断记录 | DiagnosticReports 中已满 30 天的已知诊断格式；历史内容无法重新生成 | 建议清理，标注手动选择 | 否 |
| 开发项目、构建产物与依赖中的 PKG／DMG | 位于 Git 工作区（家目录本身的仓库除外），或路径含 `DerivedData`、`.build`、`SourcePackages`、`checkouts` | 其他文件，可手选 | 否 |
| 其他位置的 DMG、普通压缩包及个人文件 | 不推断文件用途或安装状态 | 其他文件，可手选 | 否 |
| 用途未明的 App 与 Xcode 归档 | 未声明是测试副本 | 已保护；逐项确认测试用途并重新核验后可手选 | 否 |
| 发布档案与关联材料、已安装 App、命中活动使用规则的内容 | 发布位置、分发记录、安装位置或运行状态 | 已保护 | 否 |
| 开发依赖、虚拟环境和 Git 版本资料 | 保守名称边界或固定环境标记 | 已保护，不展开内部文件 | 否 |
| 链接、云端占位、未完整核验的项目及文稿包 | 身份与内容边界规则 | 已保护 | 否 |

安装介质是整理候选，不代表已确认安装完成。PKG 需确认已经安装或不再需要；DMG 还需确认不是仍要保留的个人资料。当前不会挂载或解包映像，也不会用“存在同名 App”推断安装完成。可重建缓存规则之外的目录式 PKG 继续作为完整包保留；已知依赖下载缓存内的安装介质仍按缓存规则核验，符合条件时可默认勾选。ZIP、ISO、稀疏映像及普通文件不会仅凭体积、年代或名称变成建议。已安装软件与安装介质是不同对象，空间清理不承担卸载。

这种区分参考了 Apple 的[安装流程说明](https://support.apple.com/guide/mac-help/mh35835/mac)及[磁盘映像用途说明](https://support.apple.com/guide/disk-utility/dskutl11888/mac)：下载的映像和安装包可用于安装，而磁盘映像也可存放任意文件。发布保护以已识别的发布位置、分发记录和关联材料为依据，签名或公证本身不把所有第三方安装介质变为发布原件。

## 测试包与发布材料

发布档案、已识别的 Organizer 分发归档、关联符号和更新材料可查看但受保护。已安装和正在运行的 App 不通过此功能卸载。签名、公证、名称、大小或年代本身均不能证明一个 App 是测试副本。

未知 App 与归档默认保留；可确认用途的项目在行首提供解锁操作并标注「可确认用途」，点击在右侧详情展示说明与确认。用户逐项确认仅用于测试后，使用绑定当前文件身份及目录内容的声明仅重新核验这一项，之后仍需手动选择；其他项目的身份、选择与保护状态保持不变。声明不会覆盖发布材料、运行状态、包内部边界等保护规则；文件变化后旧声明失效。普通测试 App 中的安全内部相对链接按完整包处理，不拆开清理。

## 处理与恢复

结果页选择文件后，点击「移入废纸篓 N 项」直接处理，不再重复进入另一页复核。底部使用共享下拉选择「移入废纸篓／永久删除」，默认使用废纸篓；「记住处理方式」是独立复选框，和执行按钮组成固定操作区，窄窗口按可用宽度重排。范围与处理方式都有明确悬停和选中反馈；右侧操作组使用固定宽度，执行按钮按整个结果集的数量位数预留宽度，高度为 32 点。左侧摘要将查看已选与取消选择放在第二行并保留位置，切换处理文案或改变勾选数量不推动整组操作。勾选立即保存，已记住时切换方式会同步保存；取消记住保持本次方式，下次恢复默认废纸篓。选择永久删除时，在原结果页下方明确说明不可恢复，并要求每次重新勾选确认；保存偏好不跳过确认。所有执行入口都保留所选身份快照与事务核验。

每个项目在执行前重新核对根目录、祖先目录、对象身份、内容及保护规则。处理使用同卷私有隔离目录和无覆盖移动，意图与结果逐项写入本机历史。取消只停止后续操作，当前项目完成必要的安全收尾；退出 App 等待该屏障。

移到废纸篓不记为已经释放空间。历史可按批次或按项恢复；遇到原位置同名文件时，选择保留两份或跳过，不覆盖现有文件。项目先移入同目录的私有隔离目录、核验后再交给系统废纸篓，隔离目录随后移除，因此 Finder 的「放回原处」不作为恢复途径；恢复以清理记录为准（App 重新启动后仍可从废纸篓核验恢复），也可以从废纸篓手动拖回。「永久删除剩余项目」仅处理指定批次中身份与内容仍然匹配的项目，不清空系统废纸篓。永久删除不可恢复。处理或恢复后，本批实际处理过的项目（包括跳过和需核对的项目）以及与它们路径相同、包含或被包含的结果移出当前列表；其余结果保留原核验快照并继续可选，不必重新扫描，执行前仍逐项重新核验身份、内容、运行状态和保护规则。中途停止时，尚未开始的所选项目保持勾选。列表摘要说明已移出的数量。

清理结束进入独立完成页，展示实际成功项目数、成功处理项目占用、可恢复数量及跳过、取消和需核对情况。全部失败或取消不显示成功结论；移入废纸篓不声称释放了空间。完成卡片内提供查看清理记录、返回首页和可用时的恢复入口；扫描结果中仍有项目时，另以「返回扫描结果」作为主要操作并说明剩余可复核数量，以便继续选择。点击返回首页才回到扫描准备页，首页不显示处理回执。从完成页打开的清理记录返回完成页。恢复或批次永久删除完成后回到清理记录。

处理记录是子级页面，保留返回入口。列表汇总每批日期、处理方式、项目数、扫描时磁盘占用及结果，右侧使用「展开项目／收起项目」文字和箭头，整行均可展开。展开后逐项展示名称、原路径、文件大小、磁盘占用及真实处理状态，图标由记录的目录属性和扩展名决定，不为显示图标重新读取原文件。恢复与 Finder 操作按真实状态提供；永久删除每次仍需新的不可恢复确认。

记录支持按项目名称、原路径、日期、处理方式和状态搜索，忽略大小写，多个词共同匹配。搜索结果自动展开匹配项目，分别显示匹配数与原批次总数，批次占用仍为完整记录的总量。搜索期间仅保留逐项恢复，隐藏完整批次恢复／删除，防止操作未显示的文件；清除搜索恢复批次操作。日期按照工作台时区格式化，历史未记录的信息不从当前文件位置推断。

历史损坏或无法可靠保存时，保留原记录并暂停文件处理。重启只核验未完成意图和可恢复位置，不重放删除操作。无法确认位置的项目保留人工核对说明。早期清理记录仍通过原服务访问。

处理记录由完整快照 `history.json`（早期版本可读）和同目录的追加日志组成：每次状态变化只追加一条完整记录并落盘，日志增长到与快照相当时再整理回快照，写入量不随历史长度增长。读取时按更新时间合并两者，整理中断或早期版本改写快照都不会让较新的状态丢失。日志末尾未写完的一行视为未确认的写入，读取时忽略、下次写入前清除；其他无法解析或被外部修改的内容按损坏处理并暂停文件处理。在用记录达到 1 万条时，最早的、所有项目都已结束（已永久删除、已恢复、已跳过、已取消或失败）的批次自动移入同目录的归档文件，保留在本机但不再显示在列表中；在废纸篓、待核对或处理中的记录始终保留。若全部在用记录都仍可恢复或待核对，新处理暂停并说明原因，已有记录的恢复与永久删除不受影响。读取或写入失败后，重新打开清理记录或开始扫描会以磁盘内容为准重新加载并核对，成功后解除暂停，无需重启 App。

启动和打开处理记录时，废纸篓中的项目只核对位置与身份元数据（同一对象、长度和修改时间），不重读全部内容；恢复和永久删除执行前仍完整核验内容。暂时无法读取（权限不足、所在卷未挂载、目录尚未下载等）不改变可恢复状态：恢复入口保留并在下次重新核对，恢复或永久删除也只提示稍后重试。只有确认项目已不在记录位置或已经变化时，才转为人工核对。原父目录仅权限变化时按暂时无法访问处理；被删除或替换时转为人工核对。此前因暂时无法读取而转为人工核对的移入废纸篓记录，若在原记录位置重新完整核验一致，会恢复入口；永久删除、恢复中断或仍在隔离目录的记录不在此列。

## 实现与验证

`SpaceCleaningCore` 负责只读扫描、识别和政策核验；`SpaceCleaningTransaction` 负责内容证据、持久历史、隔离、恢复及永久删除。原生模型连接系统废纸篓、文件选择器、快速预览、运行应用与磁盘读数，视图保留工作台背景、导航与头部，卡片直接复用其他模块的主题表面与全局界面不透明度，并使用原生光隙动效；系统减少动态效果、后台或不可见时暂停装饰动画。扫描计数独立于动画。

核心测试以及 `--space-cleaning-check` 使用隔离测试目录和注入的废纸篓实现。专项检查同时验证真实模型流程与普通、窄、大窗口中的生产 SwiftUI 界面。`--space-cleaning-workspace-check` 聚焦新版准备页、结果侧栏、处理记录和宽度适配；历史搜索的纯数据检查覆盖名称、路径、状态、日期与匹配范围。独立的 `--space-cleaning-model-check` 只运行后台模型回归，不创建窗口或扫描个人目录，也不替代原生界面验收。常规 `--self-check` 包含这些检查；系统权限与真实用户目录的覆盖情况仍以运行时结果为准。
