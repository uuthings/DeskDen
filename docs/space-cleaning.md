# 空间清理

空间清理使用独立导航，与体检评分分开。进入页面不会扫描或选择文件；选择全局范围并点击「开始扫描」后，一次检查当前用户的已知缓存、开发、下载和个人文件位置。范围只有「全局扫描」和「自定义位置」两种；自定义支持系统选择器多选文件夹、逐项移除和保存位置。

首页以同一张扫描准备卡承载动效、范围和开始操作。全局显示常用位置的覆盖说明；切换自定义后直接在卡片内添加、移除和保存目录，不切换到另一张编辑页面。已选目录以文件夹卡片显示名称和父路径，较多目录在位置区域内部滚动。取消草稿保留原范围和扫描结果，保存范围不会自动扫描；也可以直接开始扫描并应用草稿。规则入口紧随卡片。结果页左上方的「扫描设置」回到该首页，右侧保留重新扫描和清理记录。

## 扫描与分类

- 首页可选择「空间清理」或「大文件扫描」，两种模式复用全局／自定义范围。大文件默认下限 100 MB，可选 500 MB、1 GB 或自定义 MB／GB，下限必填、上限可选，单位按十进制计算。阈值针对普通文件的逻辑大小；目录与 App、文稿包不拆开当作普通大文件。权限与保护边界同样适用。
- 大文件模式从文件元数据尽早筛选，默认按文件大小降序，所有结果均不预选，即使文件恰好属于已知缓存。大小只是查看依据，不证明可以删除。显示逻辑大小和磁盘占用，汇总与已选占用按已分配大小计算；稀疏文件不能把逻辑长度计成可释放空间，APFS 克隆和快照也可能使实际回收量不同。
- `node_modules`、`.git`、`.venv`、`venv`、`bower_components`、`__pypackages__` 以及具有普通 `pyvenv.cfg` 标记的环境保持保护。名称只是保守保留依据，不证明内容可重建；默认不会深入统计内部容量或逐个提供删除。展开详情后可主动选择「仅统计占用」，只读普通文件元数据、不跟随链接、不跨卷，并限制条目与深度；支持取消，完整、部分和未知容量分别展示，统计不会解除保护。直接选择内部目录、通过链接选择目录、旧扫描结果及历史永久删除也不能绕过保护；已有废纸篓记录仍可恢复。npm 等下载缓存与安装后的项目依赖分开识别。
- 默认位置包括已知浏览器与依赖缓存、其他应用缓存、诊断记录、Xcode DerivedData 与 Archives、开发构建、下载内容，桌面、文稿、影片、图片、音乐、公共、开发和用户应用目录，以及 Application Support 下的发布档案。发布档案发现只读取相应位置，不把 Application Support 整体视为缓存。
- 系统目录、其他用户、外接卷和未下载的云端占位内容不自动纳入。权限不足、缺失目录、符号链接、重复身份以及扫描数量与深度限制分别记录，不能据此声称覆盖了整块磁盘。
- 「可重建内容」使用明确路径和内容规则；DerivedData 单独识别构建与索引位置。近期诊断、锁文件、数据库和运行中的关联应用内容保留。其他文件进入人工复核，不根据体积或修改时间自动推荐。
- 建议列表与默认勾选使用两层规则：列表包含值得整理的候选；默认勾选只包含明确识别、内容核验完整且当前未命中使用或保护规则的浏览器缓存、依赖缓存和 DerivedData 可重建内容。可重建缓存规则之外的安装介质，以及诊断日志、个人文件、测试包与未知内容不自动勾选；默认勾选不执行任何文件操作。
- 结果默认显示「建议清理」，与「其他文件」「已保护」分开。没有符合规则的推荐项时明确说明原因。列表展示名称、父目录、类型、修改日期和大小，支持加宽搜索、查看全部已选以及当前可见项全选；名称、所在目录、类型、修改日期、大小均可点击表头排序，再次点击反转方向。相同值按路径稳定排列，排序和筛选不改变勾选身份；表头和每行使用相同的选择控件。展开文件可预览或在 Finder 中定位；只有缓存、保护及用途确认等具体规则展示处理说明，不重复普通文件的通用提醒。只有列表内部滚动，工具栏与操作区固定。
- 扫描先发现项目，再逐项核验。发现阶段总量未知，不显示估算百分比；核验阶段用已完成项目数与已发现总数计算进度。发现与核验分别使用有界预算，避免大型个人目录挤掉已发现缓存的核验机会。核验时优先处理已识别且未受保护的可重建候选，开发环境目录只识别边界，容量需主动选择「仅统计占用」；其他保护目录沿用有界容量统计，并保留具体保护原因。取消或失败结果仅供查看；达到数量或深度边界时显示覆盖不足，未完成核验的项目不会选中。
- 扫描位置采用独立草稿。取消或保存未变范围保留现有结果与勾选；范围改变后清空旧结果、回首页，等待用户开始扫描。重叠目录合并，保存安全作用域书签供下次使用。
- 容量条显示系统报告的磁盘占用；列表区分文件大小与磁盘占用，受保护且未统计的目录显示未知，不以零表示其大小。汇总并不承诺实际释放量，稀疏文件、克隆、快照、硬链接和废纸篓会影响实际占用。

## 整理建议与默认选择

规则先判断保护、使用状态、文件身份及核验是否完整，再判断是否值得整理，最后决定是否默认勾选。允许手动处理不等于自动推荐，出现在建议列表也不等于已经选中。

| 内容 | 识别依据 | 结果分类 | 默认勾选 |
| --- | --- | --- | --- |
| 浏览器、依赖及 Xcode 可重建缓存 | 已知位置、明确内容规则、完整核验且关联应用或工具未运行 | 建议清理 | 是 |
| 文件式 PKG 安装包 | 已扫描位置中未命中可重建缓存规则的普通 `.pkg` 文件；优先排除保护规则 | 建议清理，标注手动选择 | 否 |
| 下载、桌面中的 DMG | 当前用户 Downloads/Desktop 下的普通磁盘映像文件 | 建议清理，标注手动选择 | 否 |
| 旧诊断记录 | DiagnosticReports 中已满 30 天的已知诊断格式 | 建议清理，标注手动选择 | 否 |
| 其他位置的 DMG、普通压缩包及个人文件 | 不推断文件用途或安装状态 | 其他文件，可手选 | 否 |
| 用途未明的 App 与 Xcode 归档 | 未声明是测试副本 | 已保护；逐项确认测试用途并重新核验后可手选 | 否 |
| 发布档案与关联材料、已安装 App、命中活动使用规则的内容 | 发布位置、分发记录、安装位置或运行状态 | 已保护 | 否 |
| 开发依赖、虚拟环境和 Git 版本资料 | 保守名称边界或固定环境标记 | 已保护，不展开内部文件 | 否 |
| 链接、云端占位、未完整核验的项目及文稿包 | 身份与内容边界规则 | 已保护 | 否 |

安装介质是整理候选，不代表已确认安装完成。PKG 需确认已经安装或不再需要；DMG 还需确认不是仍要保留的个人资料。当前不会挂载或解包映像，也不会用“存在同名 App”推断安装完成。可重建缓存规则之外的目录式 PKG 继续作为完整包保留；已知依赖下载缓存内的安装介质仍按缓存规则核验，符合条件时可默认勾选。ZIP、ISO、稀疏映像及普通文件不会仅凭体积、年代或名称变成建议。已安装软件与安装介质是不同对象，空间清理不承担卸载。

这种区分参考了 Apple 的[安装流程说明](https://support.apple.com/guide/mac-help/mh35835/mac)及[磁盘映像用途说明](https://support.apple.com/guide/disk-utility/dskutl11888/mac)：下载的映像和安装包可用于安装，而磁盘映像也可存放任意文件。发布保护以已识别的发布位置、分发记录和关联材料为依据，签名或公证本身不把所有第三方安装介质变为发布原件。

## 测试包与发布材料

发布档案、已识别的 Organizer 分发归档、关联符号和更新材料可查看但受保护。已安装和正在运行的 App 不通过此功能卸载。签名、公证、名称、大小或年代本身均不能证明一个 App 是测试副本。

未知 App 与归档默认保留；可确认用途的项目在行首提供解锁操作并标注「可确认用途」，点击在行内展示说明与确认。用户逐项确认仅用于测试后，使用绑定当前文件身份及目录内容的声明仅重新核验这一项，之后仍需手动选择；其他项目的身份、选择与保护状态保持不变。声明不会覆盖发布材料、运行状态、包内部边界等保护规则；文件变化后旧声明失效。普通测试 App 中的安全内部相对链接按完整包处理，不拆开清理。

## 处理与恢复

结果页选择文件后，点击「清理 N 项」直接移入废纸篓，不再重复进入另一页复核。底部直接并列展示「移入废纸篓／永久删除」，默认使用废纸篓；「记住处理方式」是独立复选框，与两种方式和执行按钮始终同一行，较窄窗口仅把选择摘要移到上一行。范围与处理方式都有明确悬停和选中反馈；处理方式和执行按钮预留稳定宽度，切换或改变勾选数量不推动整组操作。勾选立即保存，已记住时切换方式会同步保存；取消记住保持本次方式，下次恢复默认废纸篓。选择永久删除时，在原结果页下方明确说明不可恢复，并要求每次重新勾选确认；保存偏好不跳过确认。所有执行入口都保留所选身份快照与事务核验。

每个项目在执行前重新核对根目录、祖先目录、对象身份、内容及保护规则。处理使用同卷私有隔离目录和无覆盖移动，意图与结果逐项写入本机历史。取消只停止后续操作，当前项目完成必要的安全收尾；退出 App 等待该屏障。

移到废纸篓不记为已经释放空间。历史可按批次或按项恢复；遇到原位置同名文件时，选择保留两份或跳过，不覆盖现有文件。「永久删除剩余项目」仅处理指定批次中身份与内容仍然匹配的项目，不清空系统废纸篓。永久删除不可恢复。恢复及处理后，原扫描选择失效，需要重新扫描。

清理结束进入独立完成页，展示实际成功项目数、成功处理项目占用、可恢复数量及跳过、取消和需核对情况。全部失败或取消不显示成功结论；移入废纸篓不声称释放了空间。完成卡片内提供返回首页、查看清理记录和可用时的恢复入口。点击返回首页才回到扫描准备页，首页不显示处理回执。恢复或批次永久删除完成后回到清理记录。

记录的批次摘要可整块点击展开。每个项目的状态、恢复和 Finder 操作共用水平中线，说明与路径放在下方；批次永久删除在右侧使用明确按钮，每次仍需要新的不可恢复确认。

历史损坏或无法可靠保存时，保留原记录并暂停文件处理。重启只核验未完成意图和可恢复位置，不重放删除操作。无法确认位置的项目保留人工核对说明。早期清理记录仍通过原服务访问。

## 实现与验证

`SpaceCleaningCore` 负责只读扫描、识别和政策核验；`SpaceCleaningTransaction` 负责内容证据、持久历史、隔离、恢复及永久删除。原生模型连接系统废纸篓、文件选择器、快速预览、运行应用与磁盘读数，视图保留工作台背景、导航与头部，卡片直接复用其他模块的主题表面与全局界面不透明度，并使用原生光隙动效；系统减少动态效果、后台或不可见时暂停装饰动画。扫描计数独立于动画。

核心测试以及 `--space-cleaning-check` 使用隔离测试目录和注入的废纸篓实现。专项检查同时验证真实模型流程与普通、窄、大窗口中的生产 SwiftUI 界面。独立的 `--space-cleaning-model-check` 只运行后台模型回归，不创建窗口或扫描个人目录，也不替代原生界面验收。常规 `--self-check` 包含这些检查；系统权限与真实用户目录的覆盖情况仍以运行时结果为准。
