# Home and navigation

The home page uses a cyan-and-amber background and milky translucent cards in light mode. The appearance control switches to dark glass and the ink-and-gold background; its choice persists through the existing appearance preference. Both modes share a centered top navigation bar. Only the active destination expands its label by default; hovering or keyboard-focusing another destination reveals the same white capsule treatment. Navigation expansion eases over 340 milliseconds with a brief hover-intent delay. Card hover feedback changes the surface without moving its position.

The desktop layout places the device summary at the upper left, an independent month calendar at the upper right, and the greeting, clock, date, and weather between them. Storage, live network traffic, and pending items share a compact lower row anchored to the bottom of the available viewport. Short windows scroll rather than compressing content. The wider device card groups temperatures, actual fan speeds, power, and memory without a large internal gap. Cards use 14-point content insets. The page reflows at smaller widths instead of scaling the typography.

Data remains connected to the existing device, calendar, weather, and cleanup services. Storage uses actual capacity readings rather than fabricated application or document categories. Reclaimable storage is an operating-system estimate; cleanup recommendations are available only after a scan and are not treated as guaranteed recoverable space. Network readings and the recent trend cover all local traffic.

Calendar selection reveals that day's actual events and reminders in a compact attached section below the month, without opening a popover. It does not remove unrelated pending items from the home list. Events remain read-only; reminders retain completion, editing, and undo. Reminder colors distinguish known source types because custom source colors are not currently supplied by the data model.

The white linear desk mark and DeskDen name form the brand entry, with no hover background. The compact desk mark is 20 points and the DeskDen name is 14 points. The version sits at the lower right of every page, on a subtle dark backing to remain legible over either artwork. The brand menu retains minimize, fullscreen, close-window and update commands. Application quit remains in the menu bar, with a fallback in the brand menu if the menu bar icon is disabled. The arrowless account menu only identifies the local macOS account; it does not imply an online sign-in service. A light stroke follows the greeting outline once every ten seconds; reduced motion, application inactivity, or a hidden window stops the animation. All modules and their dialogs share the new appearance. Their real data and actions remain connected to their existing models.

## Shared appearance and layout

Light mode pairs cyan-and-amber artwork with milky translucent cards; dark mode pairs ink-and-gold artwork with charcoal glass. The shared palette defines text, controls, borders, progress tracks and semantic green, amber and red states. Appearance can follow macOS or be explicitly light/dark. The header and launcher controls update the same persisted preference. The former theme and opacity fields remain readable for configuration compatibility, but the UI no longer offers those visual variants or a material opacity slider.

The 58-point top navigation and 24-point left/right content gutters stay fixed across window sizes. The brand mark, page title and card boundary share the same leading edge. Standard module headers use 22-point outlined text, a 12-point subtitle, a 54-point header region and 18 points before content. Cards use 14-point padding and 12-point gaps. Detail content shares the outer reading boundaries; long pages scroll without enlarging typography. Settings adds a category row above its content. Floating Mini panels preserve their notch geometry and packing while using the same material pair.

## Local acceptance

The opt-in `--home-fluid-check --interface-fluid-check` fixture exercises the mounted production home and all main routes in both appearances at regular, narrow and wide window sizes. It uses disposable data, disabled account sources and fake calendar/notification adapters. It checks real navigation and dialogs rather than screenshots alone. Mini appearance and layout checks use the separate `--mini-appearance-check` fixture. Neither fixture establishes real account availability or system permission grants.
