# Home and navigation

The home page uses a cyan-and-amber background and milky translucent cards in light mode. The appearance control switches to dark glass and the ink-and-gold background; its choice persists through the existing appearance preference. Both modes share a centered top navigation bar. Only the active destination expands its label by default; hovering or keyboard-focusing another destination reveals the same white capsule treatment. Navigation expansion eases over 400 milliseconds. A brief delay after leaving the whole navigation strip prevents animated capsule edges from repeatedly collapsing and expanding under a stationary pointer. A fixed native input surface keeps the pointer target stable while the capsules animate; small hand movement during recentering does not activate a neighbor. Appearance, settings, account and close-window controls use matching 32-point targets and 15-point glyphs, with a quiet translucent hover surface and subtle pressed feedback. Card hover feedback changes the surface without moving its position.

The desktop layout places the device summary at the upper left, an independent month calendar at the upper right, and the greeting, clock, date, and weather between them. Storage, live network traffic, and pending items share a compact lower row anchored to the bottom of the available viewport. Short windows scroll rather than compressing content. The wider device card groups temperatures, actual fan speeds, power, and memory without a large internal gap. Cards use 14-point content insets. The page reflows at smaller widths instead of scaling the typography.

Data remains connected to the existing device, calendar, weather, and cleanup services. Storage uses actual capacity readings rather than fabricated application or document categories. Reclaimable storage is an operating-system estimate; cleanup recommendations are available only after a scan and are not treated as guaranteed recoverable space. Network readings and the recent trend cover all local traffic.

Calendar selection reveals that day's actual events and reminders in a compact attached section below the month, without opening a popover. It does not remove unrelated pending items from the home list. Events remain read-only; reminders retain completion, editing, and undo. Reminder colors distinguish known source types because custom source colors are not currently supplied by the data model.

The white linear desk mark and DeskDen name form the brand entry, with no hover background. The compact desk mark is 20 points and the DeskDen name is 14 points. The 10-point version follows the name on the same text baseline at the upper left; it no longer overlays the page footer. The brand is display-only. The separate close-window control hides the workbench while the app keeps running; application quit remains in the macOS application and status menus. Available updates retain their dedicated header entry. The arrowless account menu only identifies the local macOS account; it does not imply an online sign-in service. A light stroke follows the greeting outline once every ten seconds; reduced motion, application inactivity, or a hidden window stops the animation. All modules and their dialogs share the new appearance. Their real data and actions remain connected to their existing models.

## Shared appearance and layout

Light mode pairs cyan-and-amber artwork with milky translucent cards; dark mode pairs ink-and-gold artwork with charcoal glass. The shared palette defines text, controls, borders, progress tracks and semantic green, amber and red states. Appearance can follow macOS or be explicitly light/dark. The header and launcher controls update the same persisted preference. Workbench appearance changes use a 340-millisecond native compositor crossfade on the retained content scene, preserving the current route and view state without rendering a full-window bitmap; reduced-motion preferences disable the transition. The header theme icon turns around its center vertical axis over the same interval, switching faces at the edge without mirroring the glyph. The header stays outside the fading content scene so the previous icon cannot cover the turn; rapid toggles reverse toward the actual preference instead of queueing delayed changes. Saving appearance does not rebuild the unrelated search index or a hidden launcher. The former theme and opacity fields remain readable for configuration compatibility, but the UI no longer offers those visual variants or a material opacity slider.

The 58-point top navigation and 24-point left/right content gutters stay fixed across window sizes. The brand mark, page title and card boundary share the same leading edge. Standard module headers use 22-point outlined text, a 12-point subtitle, a 54-point header region and 18 points before content. Cards use 14-point padding and 12-point gaps. Detail content shares the outer reading boundaries; long pages scroll without enlarging typography. Settings adds a category row above its content. Floating Mini panels preserve their notch geometry and packing while using the same material pair. Light Mini cards add a one-point neutral outline so adjacent surfaces remain distinct.

## Module entry and popups

Standard action buttons and selectors share a fixed 32-point height and eight-point corner radius. Compact 28-point actions remain available for separate content rows, but do not mix with regular selectors in a toolbar. Neutral control borders keep the same color and width at rest, on hover and when pressed. Hover uses a gentle 180-millisecond fill transition without resizing; icon actions do not acquire a new outline. Reduced motion removes the transition. Supporting notes outside cards have a shared material backing so their text remains readable over both backgrounds.

Mini display preferences use the same equal-width grid for header information, built-in cards and service cards, with up to four columns. Checkboxes have 16-point marks and 32-point rows. Changing the pointer preference does not reapply the window appearance or redraw every desktop widget; actual appearance and card preference changes keep their normal update paths.

Primary navigation opens each module at its root, including when the current module is selected again. Internal links retain their requested detail. Existing readings, filters, selection and queries survive root navigation. Active cleaning scans or transactions keep their progress screen; open editors and unapplied price or scan-scope drafts must be saved or cancelled first. The Mini disk card opens space cleaning, while memory and thermal cards keep their corresponding device details.

Custom selectors, the account view, usage icon choices, device meter styles and desktop-widget actions share an arrowless popup surface: a ten-point radius, five-point trigger gap, screen-edge placement, theme-aware material, and Escape/outside-click dismissal. Clicking the trigger again closes action popups. Native macOS status and context menus retain system behavior. Space Cleaning uses its dedicated preparation, scanning, split-result and searchable-history pages; its safety and confirmation rules remain unchanged.

## Local acceptance

The focused `--control-surface-check` fixture verifies button/selector heights, neutral dropdown borders through feedback states, supporting-note contrast and checkbox stability after appearance and cursor updates. Its rendering window stays hidden; it neither moves the system pointer nor saves real preferences. Actual pointer and page-layout acceptance is performed separately.

The opt-in `--home-fluid-check --interface-fluid-check` fixture exercises the mounted production home and all main routes in both appearances at regular, narrow and wide window sizes. It uses disposable data, disabled account sources and fake calendar/notification adapters. It checks real navigation and dialogs rather than screenshots alone. Mini appearance and layout checks use the separate `--mini-appearance-check` fixture. Neither fixture establishes real account availability or system permission grants.

The focused `--interaction-feedback-check` fixture covers ordinary card clicks during a data redraw, small pointer movement, keyboard activation, stationary hover cursors, and chart projection with an hour of synthetic history. Ordinary device cards accept up to four points of movement before cancelling a click and do not paint a green focus border. Mini editing gestures leave child card clicks enabled outside edit mode. Chart rendering projects the visible samples and axis once per update, preserving gaps and both network series without changing collection frequency.

The focused `--module-navigation-check` fixture verifies root entry and deep links independently, including unsaved-editor protection, without opening a window or starting data collection. Pointer checks also cover animated navigation targets, padding, drag cancellation and stationary refresh. The `--mini-activation-check` fixture waits for real pointer clicks to verify first-click window activation and destination routes.

## Live process presentation

Process display uses explicit application-group and individual-process choices, each retaining its own label and selected state. Both choices and the sort selector share the 32-point control height. Changing the selected sort or a column heading applies immediately; incoming readings update values without continuously rearranging rows. The refresh-order action reapplies the current sort to the latest readings. Application expansion remains on each group row, separate from the display mode.

The process page uses quiet filled control feedback without extra white or colored button outlines. Custom native selectors suppress the system focus ring while keeping keyboard menu controls. Card surface outlines remain unchanged.

Each new reading builds one background projection shared by the list and filter counts. Cached aggregates avoid repeatedly summing every application's members inside sort comparisons; rendering and hover read the published snapshot. Only the latest pending query may publish. Sampling frequency, real application identity, missing-value semantics and process-action revalidation remain unchanged. The isolated `--process-presentation-check` entry exercises asynchronous replacement and ordering with synthetic readings, including a 1,324-process comparison with the previous algorithm.
