# 历史记录与长期运行

历史保留与内存缓存分别设限。磁盘上的历史总量不决定界面需要同时加载的明细量，缓存也不能只依赖单轮扫描预算。

## 网络记录

- 实时设备曲线仅在工作台可见时追加，保留最近一小时；后台流量采集继续按既有设置运行。
- 每个网络账本保留最近 400 个有记录的日期，淘汰的日期汇入最多 120 个较早月份。月份只保存实际接收／发送字节、采集覆盖及间断信息；年汇总由月数据和未归档日数据生成，不另存一套重复累计。
- 日数据与已归档数据互不重叠。归档水位阻止系统时间倒退时重新建立已归档日期。部分月的自定义查询不能精确拆回日数据，明确提示缺失部分，不按比例制造流量。
- 旧 JSON 自动兼容；升级前已经丢弃的日期无法恢复。无记录不代表零流量，短时缺口、睡眠、退出和计数器重置仍使用原有覆盖规则。
- 常规采样将更新合并，每份文件约 30 秒落盘一次；每个存储只维护一个等待任务。失败保留待写状态并重试。休眠尽力保存，正式退出冻结新采样、等待在途采集并强制保存；失败阻止本次退出并提示原因。异常终止可能损失最近尚未落盘的采样，不能承诺断电零损失。

## AI 用量

- Token 明细最多 20,000 条、31 天；到期明细汇成每个来源的 UTC 月度 Token 数，最多保留最近 120 个月。月汇总不保留会话标识、文件路径、模型明细或正文，也不据此推算订阅额度。
- 「Token 活动记录」保留近期列表，并增加独立月度汇总。近期筛选不改变月度保留范围；已断开来源仍可查看已经记录的历史。
- 旧版账本原样读取并升级为第二版格式，保存前保留上一份有效文件；未知新格式、无效数据和读取错误不通过重建空文件掩盖。年度合计只覆盖真实采集数据，旧版已过期或因容量被截去的记录不能补造。
- 归档边界单调前进，重复扫描、重新连接旧日志和系统时间倒退不会重新累计已汇总的明细。达到解析或明细容量上限时明确标记历史可能不完整，不把部分结果宣传成完整账户账单。
- 解析缓存只在内存保存计量字段，最多 400 个文件、28,000 条计量项、16 MiB 估算成本；这是缓存预算，不是整个应用的内存承诺。旧来源、关闭来源、消失和过期文件在下一次扫描时淘汰。超过缓存预算的文件可解析但不缓存。未确认来源的预览使用独立短命缓存。
- 单个文件流式读取并限制解析结果，单轮仍有文件数量、输入字节和目录条目预算。合并、校验及周期历史写入由后台串行存储处理，未变化的记录不重复重写；正式退出等待在途刷新及必要保存。

## 验证边界

核心回归覆盖一年等量 Token 记录、跨日淘汰、重复扫描、旧格式迁移、时钟回退、长年容量上限、来源轮换和缓存失效；网络回归覆盖多年日／月汇总、部分区间和写入合并。

合成数据回归证明这些路径的数量与累计边界，不等同于整机连续运行 24／72 小时的内存、CPU 或界面流畅度验收。实际资源验收必须独立记录，包含持续新增与删除日志、来源切换、休眠唤醒及异常恢复，不从短样本外推全年性能。
